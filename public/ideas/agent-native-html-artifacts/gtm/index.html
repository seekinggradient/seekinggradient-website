MadeWeb GTM strategy

A launch plan for a personal web shelf of live artifacts.

MadeWeb should not enter the market as another AI website builder. It should introduce a lighter behavior: your AI made something useful, MadeWeb gives it a URL, a shelf, and a way to spread.

Core promise

Prompt it, publish it, share it. A personal gallery of useful little webpages, tools, cards, widgets, and single-page apps.

Positioning

The category is not “AI websites.” It is live artifacts.

The strongest wedge is not that AI can make websites. Everyone is learning that. The sharper claim is that AI creates many small, useful, moment-specific things, and those things need a durable home.

For humans, it is a simple shareable page. For agents, it is a deployment target.

Human languageA home for the little web things you make with AI.
Product languageA personal web shelf for live artifacts: explainers, planners, calculators, reports, cards, widgets, and apps.
Developer languageAn agent-native publishing surface for plain HTML artifacts with namespaces, versions, visibility, and API/CLI/MCP access.

Landing page direction

Lead with the namespace and the examples.

The landing page should make the behavior obvious in one glance: claim a namespace, publish a useful thing, share a clean URL, and let others make their own.

Audience tracks

Three audiences, one primitive.

The same product can feel approachable to nontechnical users and inevitable to agent builders if the message changes by audience while the underlying primitive stays stable.

Everyday makers“I asked AI for something useful, now I need a clean link.” Examples: trip companions, event pages, explainers, checklists, route planners, decision guides.
AI-native creators“Stop losing useful AI outputs in chat. Put them on your MadeWeb shelf.” These users already make things in ChatGPT, Claude, Gemini, Cursor, Replit, and Lovable.
Agent builders“Give your agent one obvious tool: publish_artifact.” They care about plain HTML, CLI/MCP/API access, versioning, visibility, and sandboxing.

Product surface

The shelf is the public identity layer.

The profile should not feel like social media first. It should feel like a credible collection of working objects: some public, some unlisted, some private-link, all under a creator namespace.

Launch wedge

Start with private-link useful artifacts.

The first behavior to validate is not public profile culture. It is “I made a useful little thing and need to send it to someone.” Once those private and semi-private artifacts are useful, the public shelf becomes a natural second step.

Trip guideA page made for a spouse, friend group, or family weekend.
ExplainerA concept walkthrough that is easier to share than a chat transcript.
CalculatorA one-off tool for a pricing, mortgage, classroom, or planning decision.
ReportA lightweight interactive writeup with charts, filters, and notes.

Growth loop

Every shared artifact can create the next creator.

The badge is useful, but the stronger loop is remix. A viewer should understand the artifact, trust the page, and immediately see the path to making their own version.

Channels

Launch different doors into the same product.

Show HN“Show HN: MadeWeb, an agent-native home for HTML artifacts.” Emphasize plain web files, no framework lock-in, stable URLs, version history, sandboxing, CLI/MCP, and one artifact with many surfaces.
Product Hunt“Publish the useful little web things your AI makes.” Make this visual: creator shelves, artifact cards, remixing, examples, and claim-your-namespace.
AI creator circlesPost prompt-to-published demos on X, AI newsletters, AI Tinkerers, teacher communities, indie hacker groups, and creator forums.
MCP and agent buildersLead with the tool surface: publish_artifact, update_artifact, list_artifacts, set_visibility, rollback_artifact, generate_card_view.

Pricing hypothesis

Price around artifacts, identity, and distribution.

Free10 public or unlisted artifacts, private-link sharing, MadeWeb badge, basic generated previews, public shelf.
Plus · $8-12/moMore artifacts, custom domain, remove badge, private artifacts, version history, analytics, stronger cards/widgets.
Pro / AgentCLI and MCP publishing, deploy tokens, API access, larger bundles, team namespaces, audit and rollback controls.

Do not bury API/MCP behind enterprise pricing. Agent builders are an early wedge, so give them a generous beta and charge once usage and collaboration become real.

90-day plan

Validate usefulness before chasing profile culture.

First 30 days Concierge beta with seed artifacts.
  • 50 seed artifacts, at least half private-link or unlisted.
  • 10 examples with page, card, and widget variants.
  • 10 agent builders publishing via CLI/MCP prototype.
  • 20 nontechnical users publishing from prompts with help.
First 60 days Find the strongest wedge.
  • Launch public creator shelves after private-link utility is proven.
  • Add “generate card view” as a signature feature.
  • Publish “the post becomes software” essay/demo.
  • Do Show HN with CLI/MCP demo.
First 90 days Turn usage into a repeatable loop.
  • Product Hunt launch around the visual artifact shelf.
  • Open template and remix gallery.
  • Launch agent publishing beta as a named program.
  • Start paid conversion around custom domains and private artifacts.

Review questions

The decisions to make before launch.

Brand promiseIs MadeWeb mainly “a home for little web things,” “a personal shelf for live artifacts,” or “a publishing target for agent-made HTML”?
First wedgeWhich initial artifact type feels most naturally shareable: explainers, trip/planning pages, calculators, reports, or dashboards?
Access modelShould early users join a waitlist, reserve a namespace, or immediately publish with a soft invite gate?
Agent betaShould CLI/MCP access be part of the first public story, or a quieter developer beta beneath the human-facing launch?
